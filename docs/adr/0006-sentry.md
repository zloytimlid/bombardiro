# ADR-0006: Sentry для ошибок сервера и клиента

- Статус: принято
- Дата: 2026-11-05

## Контекст

Раздел 13 («Наблюдаемость», «Персональные данные») и этап 5: алерты на ошибки, критерий закрытой беты —
«без критических ошибок в Sentry за 7 дней»; Sentry без PII. Сервис назван в ТЗ, но пакеты — новые зависимости.

## Решение

- Сервер: `sentry/sentry-laravel` (^4, MIT). `Integration::handles()` в `bootstrap/app.php`; `config/sentry.php`:
  `send_default_pii` жёстко `false` (не переопределяется окружением), `before_send` → `App\Support\SentryScrubber`
  (остаётся только id игрока; почта, имя, IP, cookie, авторизационные заголовки и тела запросов вырезаются).
- Клиент: `@sentry/vue` (^10, MIT), `resources/js/lib/sentry.ts` — инициализация только при `VITE_SENTRY_DSN`,
  SDK — отдельным чанком; `sendDefaultPii: false`, `beforeSend` удаляет пользователя, cookie, заголовки, тела.
- CSP: `connect-src` получает хост приёма Sentry из DSN (`SecurityHeaders`).

## Альтернативы

- GlitchTip (совместим с протоколом Sentry, можно разместить у себя) — тот же SDK, меняется только DSN.
- Только журналы и Pulse — нет группировки ошибок клиента и алертов.

## Последствия

Без DSN пакеты ничего не отправляют; разработка и тесты работают без Sentry.

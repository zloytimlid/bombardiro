# Протокол кооператива (раздел 9)

Версия протокола — `PROTOCOL_VERSION = 1` (`resources/js/game/net/schemas.ts`, `App\Domain\FlightSessions\Support\Protocol::VERSION`).
Каждое сообщение несёт поле `v`; при несовпадении клиент показывает «Версия протокола не совпадает», сервер отвечает 409.

Модель — **авторитетный хост** (ADR-0001): мир вылета считает симядро в Web Worker браузера хоста,
остальные игроки шлют ввод своей станции и рисуют интерполированные снапшоты. Сервер не считает физику:
хранит журнал, снапшот мира, выбирает хоста и пересчитывает разбор.

## Каналы Reverb

| Канал | Кто | Что |
|---|---|---|
| `presence-crew.{crew}` | все члены экипажа | присутствие (кто на связи); `SeatClaimed`, `CrewReady`, `SessionStarted` |
| `private-session.{session}` | участники вылета | whisper `snap`, `event`, `cmd`, `ping`, `pong`; серверные `HostChanged`, `SessionEnded` |
| `private-session.{session}.input.{seat}` | владелец места и хост | whisper `input` (ввод станции) |
| `presence-flight.{flight}` | члены экипажей звена (этап 6) | whisper `pos` от хоста каждого экипажа, 5 Гц: слот, положение, ориентация, состояние борта |

Авторизация — `App\Domain\FlightSessions\Support\ChannelAuth` (`routes/channels.php`): канал ввода места
доступен только тому, кто сидит на этом месте, и текущему хосту.

## Сообщения (whisper)

Схемы — zod в `resources/js/game/net/schemas.ts`; неразобранное сообщение отбрасывается с предупреждением в консоли.

| Событие | Направление | Частота | Содержимое |
|---|---|---|---|
| `input` | клиент → хост | 30 Гц при изменениях, 5 Гц без изменений | `s` место, `f` оси полёта ×1000, `g` азимут/угол установки ×10⁴, `b` кнопки (битовая маска), `a` неподтверждённые действия `[seq, action]` (≤ 32), `r` RTT |
| `snap` | хост → все | 15 Гц, ключевой кадр раз в 1 с (и по запросу) | тик, квантованные позиции/ориентации, `ack` по местам, `q` последний seq журнала; ключевой кадр `key` — экипаж, цель, повреждения (≤ 4 КБ) |
| `event` | хост → все | по мере появления | события журнала `{seq, tick, type, payload}` пачками ≤ 40; разрыв seq → `cmd events_from` |
| `cmd` | любой → все | по действию | `chat` (≤ 200 символов), `events_from`, `keyframe`, `seat_ai` (место отдано ИИ / возвращено) |
| `ping` / `pong` | клиент ↔ хост | 1 Гц | RTT до хоста; используется для компенсации задержки |
| `rtc` | участник ↔ участник | по событию | сигнализация голосового СПУ (этап 6): `offer` / `answer` (SDP), `ice`, `talk` (тангента нажата); адресат — `to`, чужие отбрасываются |

**Действия** (`WorldAction`: шасси, сброс, переключатели) нумеруются клиентом и повторяются в каждом `input`,
пока хост не подтвердит номер в `snap.ack[seat]`; хост применяет каждый номер ровно один раз (`InputDecoder`).

**Интерполяция** (`ViewInterpolator`): клиент рисует мир на 100 мс в прошлом; без снапшотов экстраполирует ≤ 250 мс.

**Компенсация задержки** стрельбы: хост откатывает истребители на RTT/2 стрелка, не больше 150 мс
(`MAX_LAG_TICKS = 9`), по истории позиций (`MissionWorld.fighterPositionAt`).

## HTTP API хоста и клиентов

| Запрос | Кто | Частота | Назначение |
|---|---|---|---|
| `GET /api/sessions/{s}/bootstrap` | все | при входе | миссия, конфиг, театр, сид, состав мест, хост, своё место |
| `POST /api/sessions/{s}/rtt` | хост — 1 с, клиенты — 5 с | пульс | отметка «на связи», RTT; ответ — текущий хост и статус |
| `POST /api/sessions/{s}/events` | хост | раз в 2 с | журнал событий пачками ≤ 500, повтор безопасен (unique `(session, seq)`) |
| `PUT /api/sessions/{s}/snapshot` | хост | раз в 2 с | полный мир `WorldStateV1` в Redis (TTL 10 мин) |
| `GET /api/sessions/{s}/snapshot` | новый хост | при миграции | последний снапшот мира |
| `POST /api/sessions/{s}/host-lost` | клиент | при пропаже хоста | запрос на выбор нового хоста |
| `POST /api/sessions/{s}/finish` | хост | в конце | итог (исход, метрики, трек); сервер ставит `ComputeDebrief` |
| `GET /api/sessions/{s}/debrief` | все | опрос 2 с | серверный разбор, `verified`, флаги |

Ограничения частоты: `session-events` 60/мин, `session-snapshot` 40/мин, `session-heartbeat` 180/мин, `api` 120/мин.

## Пропажа хоста (раздел 9.3)

1. Клиент замечает пропажу: нет снапшотов 1,5 с (проверка каждые 0,25 с) или хост ушёл из presence-канала (при обрыве без закрытия сокета presence узнаёт об уходе только по тайм-ауту).
2. `POST host-lost`. Сервер под блокировкой проверяет, что пульса хоста нет дольше 1 с,
   и выбирает участника на связи (пульс за последние 6 с) с наименьшим RTT; событие `HostChanged`.
   Пульс хоста — 2 раза в секунду из игрового кадра, порог молчания — 1 с. Новому хосту даётся льготный срок 5 с (`NEW_HOST_GRACE_SECONDS`) на загрузку снапшота — иначе роль «скачет» между клиентами; тот же срок — первому хосту при старте вылета.
   Время пульса и сообщения о потере — момент прихода запроса в nginx (`fastcgi_param REQUEST_START $msec`, `Protocol::arrivedAt`), а не обработки в PHP: очередь PHP-FPM под нагрузкой не считается тишиной хоста.
   Если сообщение пришло раньше порога (до него ≤ 1,2 с, `HOST_LOST_WAIT_SECONDS`), сервер дожидается порога в том же запросе: пришёл пульс — отказ, нет — выбор нового хоста без повторного запроса клиента.
3. Новый хост сразу переходит на пульс 1 с, загружает снапшот мира, восстанавливает мир в своём воркере (`restoreState`),
   подписывается на каналы ввода всех мест и продолжает с тика снапшота; в журнал — `host_changed`.
4. Остальные сбрасывают буфер интерполяции и ждут ключевой кадр нового хоста. На экране — «Смена хоста…».

Откат до 2 с мира (интервал снапшота) — цена миграции; события после снапшота хост пересылает заново.

## Места

- Место держится за отключившимся 120 с (`CrewMember::SEAT_HOLD_SECONDS`); перезагрузка страницы возвращает на место.
- Пока игрока нет на связи, его станцию ведёт ИИ.
- Переход на другое место в вылете: `POST /api/crews/{c}/seats/{seat}` (занято → 409), затем 3 с задержки.
- «ИИ на моём месте» — `cmd seat_ai`; хост убирает место из списка людей.

## Серверный разбор (раздел 9.4)

`ComputeDebrief` → `DebriefCalculator`: по журналу пересчитывает поражение цели (разрывы бомб × секции цели),
время над целью и итог; итог хоста используется только для метрик станций и трека. Флаги правдоподобия:
`bombs_over_load`, `kill_before_spawn`, `kills_over_spawned`, `overspeed`, `journal_incomplete`.
Есть флаги — `verified = false`, на разборе — предупреждение. Разбор одинаков у всех участников.

## Отладка

`/play/{session}?debug_net_delay=150` (только вне продакшена) задерживает отправку и приём на 150 мс.
